# makora

A durable, self-evolving agent harness for long-running tasks, built on [pi-durable](../../packages/durable). Built
so far: the app skeleton, a persistent Python REPL as the model's one tool, `/diff` and `/fork`, subagents with their
own worktrees and the agents dashboard, `/pstack` model tiers, `/quiz`, `/review` with review subagents, and releases
with `install.sh`. See [the docs](../../docs/README.md): [vision](../../docs/vision.md), [roadmap](../../docs/roadmap.md) and
[decisions](../../docs/decisions.md).

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/mr-jones123/makora/main/apps/makora/install.sh | sh
```

Installs the newest `makora-v*` GitHub release: one bundle of makora with this repository's `packages/*`, no npm
dependencies. `makora update` updates it. Needs Node 22.19+ and uv or Python 3.11+. Releases are built with
`npm run build:release`. See [getting started](../../docs/getting-started.md) and
[development](../../docs/development.md#releases).

## Run from source

Requires Node 22.19+, the monorepo's installed dependencies and model data, and for the REPL either
[uv](https://docs.astral.sh/uv/) or `python3` 3.11+ with `venv` and `pip`. From the repository root:

```sh
npm install --ignore-scripts
npm run hydrate:model-data
cd apps/makora
npm start                      # TUI, new session in the current directory
```

`bin/makora.mjs` runs the same entry from any directory (`ln -s "$PWD/bin/makora.mjs" ~/.local/bin/makora`).

| Command | What it does |
| --- | --- |
| `makora` | New session in the current directory |
| `makora --continue` | Latest session of the current directory |
| `makora --resume [id]` | A session by id, or a picker |
| `makora ls` | List sessions |
| `makora -p "<prompt>"` | Print mode: streams the answer to stdout, tool calls to stderr, exit 1 when unanswered |
| `--fake` | Uses a scripted fake model; no provider is called, but tools act on real files |
| `--ephemeral` | Keeps the session in memory: no session files, no REPL snapshots |
| `--model provider/id` | Model for this run |

Data lives in `~/.makora` (`MAKORA_HOME` overrides it): `sessions/<id>/` per session (`session.sqlite`, REPL
snapshot `blobs/`, kernel pid files), `python/venv` (the kernels' Python environment, built by the first cell),
`auth.json`, `settings.json`, `keybindings.json`, `quizzes/` (pages from `/quiz`), and optional `AGENTS.md` and
`skills/`.

## The REPL

The model is offered one tool, `python`: a persistent kernel per conversation whose cells call `await read(...)`,
`write`, `edit`, `bash` and `llm`, each recorded by Durable. After each cell, variables and a git tree of the worktree
are saved, so a crashed kernel or a restarted makora resumes with them. `src/kernel/` runs kernels, `src/repl/` is
the tool, and `python/makora_rlm/` is the kernel's Python side. See
[features/repl.md](../../docs/features/repl.md) and [architecture/repl.md](../../docs/architecture/repl.md).

## Login

`/login` connects a provider. Claude Pro/Max logins use Anthropic's OAuth flow; Anthropic bills this usage as extra
usage, not against plan limits. Each login with a new identity adds an account; `/accounts` switches or removes
them. The status line shows the active account, plan usage when available, and a warning before the 30-day grant ends.

## Skills

pstack and no-mistakes are bundled in `skills/`, generated by `scripts/sync-skills.mjs` from the pins in
`skills.lock.json`. Never edit `skills/` by hand: change `skills-src/` (the makora adapter and overlays) and rerun
`node scripts/sync-skills.mjs`. `--check` verifies the tree, `--latest` repins upstream. The `makora-skills` workflow
checks every PR and opens a daily sync PR; it needs the repository secret `MAKORA_BOT_TOKEN`. The `no-mistakes`
binary is installed separately.

## Develop

```sh
npm run check                                              # biome + tsc for this app
node --import ./src/source.ts --test test/<file>.test.ts   # one test file
```

`test/kernel.test.ts` and `test/repl-print.test.ts` build a real Python environment, so they need uv or Python. See
[development](../../docs/development.md).
